# Changelog

## 0.1.0

- Import of the planner engine export (`hoh-engine` v1) from a zip or a folder, in two steps (files, then records after the code compiled).
- One ScriptableObject per record of a native-format schema, matched by planner ID; renames keep the asset; removed records are kept and marked.
- Your class files under `Unity/Scripts/Classes` are never overwritten.
- Validation (menu, window, CI), Inspector note on planner records, *Window ▸ Game Design Planner*.
- `hoh-engine-report.json` for the planner after every import and validation (records: done / incomplete with reasons / missing / removed; classes: written / TODOs left / missing), plus *Write report for the planner* in the menu and window.
- Linked folder support: when the planner writes the export into the folder itself, the import finishes as soon as Unity notices the new `hoh-engine.json` (setting *Import when the planner writes*).
- *Set up project*: planned folders with one assembly definition per module, and `.editorconfig`, `.gitattributes`, `.gitignore` at the project root from the plan; never overwrites (a different existing file gets a `*.planner` copy beside it).
- Addressables groups (one per planned load group, records addressed by key, planned labels) and a Unity Localization string table collection “Planner” from `strings.csv`, each in its own assembly that compiles only when that package is installed.
- `PlannerMetrics.Record(key, value)` (runtime, builds too): playtest samples for the Balance plan, summed across sessions; the report carries mean, count, spread and build. *Playtest metrics › Merge metrics file / Clear metrics*.
- Live link (off by default; 127.0.0.1, token, origin check): the planner can select a record and push its values into Play mode, restored when Play mode ends.
- Placeholders for missing art (sprites with initials in the plan’s palette, primitive prefabs), counted as missing art by the validator. Unity adapter v4 adds data-check EditMode tests and the debug console.
- Renamed classes: your class file moves to the new name with the class name inside changed and its .meta (GUID) kept, on zip import and from a linked folder.
- Greybox scenes from the location maps (floor, walls, doors, keys, spawns, lights, NavMesh with AI Navigation); channel assets for the Architecture's ScriptableObject channels; the generated Telemetry log added up into the report's metrics.
- Screens.asset filled with the planned screens' UXML after each import; the zip import also owns Unity/Tests, Unity/Input and Unity/UI (stale files there are removed).
- Performance budgets measured by the generated PlannerBudgets go into the report; audio event assets kept in step with the plan; a pseudo-locale with Unity Localization (made once).
- Build Settings scenes by roadmap phase (window section and PlannerCI.BuildScenes), from the generated PlannerScenes.
- Playable-prototype exports (manifest `requires.runtime`): the import stops before writing anything, and the linked-folder records step waits, until `com.handsofhubris.planner-runtime` in the named version or later is installed; the message says what to install or update.
- Protected re-import (same rules as the planner's linked folder, `Tests/Editor/Fixtures/ownership-cases.json`): a generated file changed by hand (or not written by the planner) stops the import before anything is written; *Overwrite (keep a backup)* or `PlannerCI.Import -hohOverwrite` replaces it. Files in generated folders the planner did not write are never deleted. Everything replaced or removed (with its .meta) is backed up under `.hoh-backup/<time>/` with a journal; a failed import is rolled back, *Tools ▸ Game Design Planner ▸ Restore last import* / `PlannerCI.RestoreLastImport` undoes the last one, *Preview import…* / `PlannerCI.Preview` lists what an import would do. An interrupted write is reported when the editor loads. CI exit code 3 = stopped on conflicts.
- Prototype scene (with `com.handsofhubris.planner-runtime` 0.3.0 or later; assembly `HoHPlanner.Bridge.Prototype`): *Tools ▸ Game Design Planner ▸ Build prototype scene* / `PlannerPrototypeScene.CI` builds `<root>/Prototype/<planned scene>.unity` from the IR's gameplay part and the location map — runtime host with the plan's modules, level at the planned map scale (default: one walkability cell per metre), URP Lit placeholder materials, sun, the player (`Prototype/Player.prefab`, made once and then yours) at the player start with the planned speed and input map, the follow camera, and a `PlannerPlacement` per start, pickup (visual: the item record's prefab, else `Prototype/Prefabs/<key>.prefab`, made once) and spawn. Labelled `PlannerPrototype`; found by the planned scenes' Build Settings step. Rebuilding keeps the scene, mesh and material GUIDs; an unchanged plan builds nothing; a scene changed in Unity stops the build (exit code 3) unless overwritten, with a copy under `.hoh-backup/`. After each record import a stale or missing prototype scene is reported. The greybox builder shares the level code and is unchanged.
- Prototype scene with interaction (runtime 0.4.0; builder version 2): each pickup gets a `PlannerPickup` with its item name, and the scene an *Interaction* object (`PlannerInteractor` at the planned range, prompt with the planned Interact key); the host requires the “interaction” module.
- Prototype scene with the inventory (runtime 0.5.0; builder version 3): an *Inventory* object with the planned slots and items, and a *HUD* object showing the planned HUD screen (the generated UXML with the HUD class) through `Prototype/UI/PanelSettings.asset` (Unity's default runtime theme; made once, then yours), bound to the inventory.
- Prototype scene with quests (runtime 0.6.0; builder version 4): a *Quests* object with the generated PlannerQuestGraph (found by its runtime interface) and `PlannerQuests` with the typed quest rules of the export; the HUD binding shows the quest tracker. Quests without the Inventory system are refused with a reason.
- Prototype scene with saving (runtime 0.7.0; builder version 5): a *Save* object with `PlannerGameState` (the player, inventory and quests, and the saved parts linked to a runtime state) and the generated PlannerSaveSlice (found by its runtime interface). A part linked to a system the plan does not choose, or Save and load without any linked part, is refused with a reason.
- Generated `PlannerSave` (Unity adapter v13): `PlannerSaveException` for a damaged or newer save or a failing migration (nothing restored), missing migration steps logged, parts restored in the planned order (`PlannerSaveKeys.Order`); EditMode tests for each.
- CI helpers for a playable-prototype project (`PlannerCIProject`, only when called): `Prepare` sets Active Input Handling to Both and makes a URP asset the default render pipeline; `BuildPlayer -hohBuildPath … [-hohBuildTarget …]` builds the Build Settings scenes. Unity adapter v14: `PlannerSaveSlice.Delete`. The planner's Unity gate (`npm run gate:unity`, `ci/planner-gate.yml`) drives them; `ci/plan-to-unity.yml` runs the generated tests with game-ci.
- Prototype scene with crafting (runtime 0.9.0; builder version 6): a *Crafting* object with `PlannerCrafting` (the export's typed recipes) and the crafting panel, opened with the planned control; the input map gets a Crafting action (Unity adapter v15) and the scene test a crafting case.
- Prototype scene with combat (runtime 0.10.0; builder version 7): a *Combat* object with the player's health, `PlannerCombat` and the generated PlannerDamageFormula (Unity adapter v16, the plan's damage formula in C#); each placed enemy with its planned values, its body (`Prototype/Prefabs/<enemy>.prefab`, made once) and its loot; the HUD health bar; the Combat save state. The input map gets an Attack action and the scene test the encounter, the player's respawn and the fight saved and loaded.
- Prototype scene with NPC dialogue (runtime 0.11.0; builder version 8): a *Dialogue* object with `PlannerDialogue` (the export's typed Dialogue lines, the quest graph for their choices, the inventory for their items) and `PlannerDialoguePanel`; each placed NPC (spawn role “npc” with a character) with `PlannerNpc` and its body (`Prototype/Prefabs/Npc<name>.prefab`, made once); the Dialogue save state. The generated PlannerQuestGraph makes choices by planner ID (Unity adapter v17), and the scene test talks to the NPC, picks the planned option and checks it once, also after saving and loading.
- Prototype scene with quick save (runtime 0.12.0; builder version 9): the *Save* object gets `PlannerQuickSave` with the planned Quick save and Quick load keys and the first manual slot; the input map gets QuickSave and QuickLoad actions (Unity adapter v18), and the scene test presses them. Saved parts whose system the plan does not choose are no longer linked, so turning a system off no longer stops the scene build. The Unity gate checks each chosen system's own evidence (extended gate), runs with `--without <systems>`, and ends its report with the export's placeholders and manual work.
- Prototype scene with several locations (runtime 0.13.0; builder version 10): every location of the prototype's world (the IR's `gameplay.world`, loading profile “one scene”) is a level from its own map, side by side at its offset, with `PlannerLocation`; the placements and spawn markers of each location are placed there; each passage gets `PlannerPassage` with its arrival at the way back on the other map. The scene's fingerprint now also covers the world, every map and the dialogue (a change of dialogue lines alone rebuilds the scene). The generated scene test goes through every passage and back and saves in another location (Unity adapter v19); the Unity gate also checks that a scene of yours is left as it is.
- Prototype scene with enemy behaviour (runtime 0.14.0; builder version 11): with Combat, a *Navigation* object (`PlannerNavigation`, baked from the levels when the game starts; the runtime needs `navigation`), and each enemy with its planned sight range, give-up range and patrol route (the line its placement names, in scene positions). The scene test checks the navigation mesh and that the enemy patrols, chases a player it sees and goes back (Unity adapter v20).
- Prototype scene with progression, trading and day and night (runtime 0.15.0; builder version 12): a *Progression* object with the planned XP table; a *Trade* object and each placed merchant (`PlannerMerchant`, its planned offers and purse, a body `Prototype/Prefabs/Merchant<name>.prefab` made once); a *Clock* object dimming the sun, whose monster strength the combat module uses; the three save states. The scene test checks levels from play, the merchant's prices, the clock and a save of all three (Unity adapter v21).
